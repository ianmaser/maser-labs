## Phase 4 — Hero Showpiece Graphic

**Goal:** Lightweight animated hero graphic with static fallback for mobile/reduced-motion.

### Assets Provided by Ian

Ian generated the hero graphic externally and provided four files:

- **HeroCanvas.tsx** — live Canvas 2D animation (icosahedron wireframe with orbital rings, edge particles, dust, bloom). 30fps cap, pauses offscreen, respects `prefers-reduced-motion`.
- **HeroBackdrop.tsx** — wrapper component. Dynamic imports HeroCanvas with `ssr: false`. Shows static poster for instant first paint; only mounts the live canvas on desktop + fine pointer + motion allowed.
- **maser-hero_2.html** — reference HTML for capturing the static poster (not integrated).
- **hero-static.webp** — 26KB static poster image for mobile/reduced-motion fallback.

Files placed in `components/hero-files/`, static asset in `public/`.

### Integration Work

1. **Initial wiring** — Imported `HeroBackdrop` into `Hero.tsx`, replaced the old `GlowContainer` background and placeholder circle. Removed `GlowContainer` import.

2. **Build fix** — HeroBackdrop.tsx had JSX code examples inside a block comment that Turbopack parsed as real JSX. Trimmed the setup comment to plain text to fix the build error.

3. **Layout iteration** — The graphic was initially wired as a full-section absolute background (z-0 behind text). Ian wanted it as an inline showpiece element *above* the headline, where the old placeholder circle was. Restructured Hero.tsx to place HeroBackdrop in a contained div above the h1.

4. **Sizing iterations:**
   - Started at `max-w-xl`, `h-64/h-80/h-96` — too small, too much black space above
   - Expanded to `max-w-4xl`, `h-72/h-96/h-[28rem]` — better but still issues
   - Final: `max-w-6xl`, `h-[22rem]/h-[28rem]/h-[36rem]` with `-mt-6`

5. **Blending fix (desktop)** — The graphic had hard edges against the dark background. Added a CSS `mask-image` with `radial-gradient(ellipse ...)` to fade the container edges smoothly into `#050506`.

6. **Composition fix** — The outermost orbital ring was clipping at the top of the canvas. Ian identified this as a composition issue in HeroCanvas.tsx, not a container sizing problem. Changed `CY` from `H * 0.42` to `H * 0.48` and `R` from `min(W,H) * 0.275` to `min(W,H) * 0.25` to give the outer ring headroom. (Ian also adjusted `CX` to `0.55` and `CY` to `0.44` via linter/manual edit.)

7. **Mobile blending fix** — On mobile, the static poster `<img>` had crisp edges where it met the layout. Added a CSS mask directly on the `<img>` element: `radial-gradient(ellipse 65% 70% at 50% 42%, black 35%, transparent 90%)`. Also removed `bg-[#050506]` from the backdrop container div — it was creating a visible box behind the masked image, fighting the fade-to-transparent effect. The live canvas didn't need this fix (it paints its own opaque background + scrim).

### Decisions Made

- Hero graphic is an **inline showpiece above the headline**, not a full-section background. This matches the original plan's reference (Ref 4/5 style) and the old placeholder circle placement.
- Pure-code hero was rejected in favor of a generated image + canvas animation — more visually rich and predictable to iterate on.
- CSS masks handle edge blending rather than modifying the image asset or canvas rendering.
- The `<img>` poster uses a native `<img>` tag (not `next/image`) intentionally — it's a decorative background element, `aria-hidden`, and the poster is already optimized at 26KB.
