- Created `leads` table with schema from plan (§8): id, created_at, source, name, email, business_name, business_type, service_interest, budget_range, timeline, project_details, status, raw_meta

### Validation (`lib/validation.ts`)
- Fixed `service_interest` from a strict enum to `z.string().optional()` — the original enum didn't match the form options in `site-content.ts` and was required when the form treats it as optional
- Added `leadSchema` as a discriminated union on `source` field, handling both `hero_hook` and `bottom_form` schemas in one parser

### API Route (`app/api/lead/route.ts`)
- Replaced stub with full implementation:
  1. Parse + validate body with zod discriminated union
  2. Capture metadata (referrer, user agent) into `raw_meta`
  3. Insert into Supabase `leads` table via service role
  4. Send email notification via Resend API
  5. Return success/error (email failure doesn't block the response — lead is already saved)
- `buildLeadRow()` maps hero hook's `project_idea` field to the DB's `project_details` column
- Return type explicitly typed as `Record<string, unknown>` to satisfy Supabase client's strict generics
